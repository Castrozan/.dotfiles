## The gap that produced it, for your call and not fixed here

The probe deduplicates a capture against open pull requests **by capture filename**, at
`agent-harness/agent-instructions/skills/ril/scripts/ril_cli/commands.py:85-92`, which derives a branch name from the filename and
skips the capture when that branch has an open pull request. A re-save of the same URL gets a new timestamp,
so it gets a new filename, so it is a new capture to the probe and nothing about the first one suppresses it.
The same holds for `#agent-work-done` at `captures.py:8`: the marker lives in the capture file, so marking
one copy says nothing about the other.

Deduplicating by resolved origin URL instead would close that, at the cost of resolving links during a probe
that today is a cheap filesystem-plus-`gh` read and runs on every gate tick. I have not built it: it is a
change to the queue's own semantics, it is not what this capture asked for, and a drop's pull request carries
its decision file alone. Say the word and it becomes its own change.
