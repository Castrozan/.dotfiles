tests, integration tests, evals, fixtures, and recorded short-term compliance did not select or justify any behavior.

describes current ownership, not the final migration decision. `Code enforcement` says whether code can safely own
the behavior: `Yes`, `Partial`, or `No`, followed by the practical mechanism. `Partial` means code can enforce only a
decidable boundary while the remaining judgment still needs instructions.

## Deployment and conflict notes

The shared core is declaratively deployed to Claude, Codex, OpenCode, and Pi through S36. Repository `CLAUDE.md` and
`AGENTS.md` are generated deployment copies of S03. Interactive communication reaches Claude, Codex, OpenCode, and Pi
through S35; the reply guard in S28 covers those keyboard-driven surfaces. Hermes does not consume the shared core: S21
is seeded by S38 only when its memory is absent, so an existing live Hermes memory can remain stale.

The most material current conflicts are intentional inputs to the next placement phase. S01 says domain policy belongs in
skills, while S04 says a skill must not be the sole authority for a persistent default. Hermes asks fewer questions than
the shared core and applies a different reply template. General coding defaults are explicit in S07 and S21 but absent
from shared core. The outward-facing approval boundary is explicit in interactive guidance and selected controls but has
no single shared authority across harnesses.
