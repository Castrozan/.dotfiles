## The origin as resolved

Read the exact post and its self-thread through the twitter skill with `twikit-cli tweet` and `twikit-cli thread`.
Herdr announced an experimental plugin on 2026-07-27 that put a live Chromium view in a Herdr pane: scroll, click,
hover, zoom and switch tabs in the pane, open localhost links beside the code, or point Playwright and other CDP tools
at the same browser so a person could watch the agent and take over without reconnecting it.

The implementation is `ogulcancelik/herdr-browser`, plugin id `official.browser`:
https://github.com/ogulcancelik/herdr-browser. It launched a dedicated Chromium profile per Herdr session, streamed
screenshots through Herdr's graphics path and exposed a view-scoped CDP gateway. It did not attach to the normal
desktop-browser profile.

That repository now marks itself **deprecated and no longer maintained** and directs users to
https://github.com/zenbu-labs/terminal-browser. The successor is not the same plugin under a new name. It replaces the
CDP-to-PNG screencast with an Electron offscreen renderer and raw RGBA frame transport, supplies its own browser CLI,
and has a different Herdr plugin (`zenbu-labs.terminal-browser`). Its current release at review time is v0.13.1,
published 2026-09-30.

## What it actually is

The useful idea is shared control, not merely showing a web page in terminal cells. The original plugin owned a
Chromium instance, rendered that instance inside the multiplexer and let a CDP automation client and the pane's human
input act on the same targets. That made an otherwise headless automation run observable and interruptible in the
workspace where the agent was already running.

The captured artifact itself is now an abandoned implementation of that idea. Its replacement is a standalone browser
application that happens to integrate with Herdr. The replacement's Linux x64 release archive alone is about 135 MB,
it ships an Electron browser and a separate persistent state tree, and usage telemetry and crash reporting are on
unless disabled (`DO_NOT_TRACK=1` or the tool-specific settings). The published Herdr plugin's build step is an
imperative `curl | bash` installer, so fitting it here would require pinning and packaging the release rather than
running the upstream installer during activation.

`agent-harness/agent-instructions/skills/workstation/browser/SKILL.md:8-18` sends interactive work to the user's real
Chrome Global profile and unattended work to an isolated PinchTab profile, while
`agent-harness/agent-instructions/skills/workstation/browser/install/default.nix:14-18,55-58` packages PinchTab
declaratively. Terminal Browser would be a third isolated browser/profile. It would replace neither route: it cannot
reuse Chrome Global's logins, and it does not remove PinchTab's unattended-browser role. What it adds is inline
visibility and shared mouse control, but no current module, skill or agent is blocked for lack of that presentation.

## Reasoning

Drop the capture rather than install either project.

1. The thing captured is no longer maintained. Installing it after its maintainer has named a successor would create a
   dependency with no supported future.
2. Adopting Terminal Browser instead would silently change the evaluated artifact. It is a separate Electron browser,
   release stream, state directory, telemetry surface and Herdr integration, not a maintenance release of the captured
   CDP viewer.
3. The repository already owns working browser automation with two deliberate trust profiles: the user's real browser
   for interactive work and PinchTab for unattended work. The successor adds operational and policy surface without
   deleting either one or unblocking a named workflow.
4. This is not worth filing as a reference. The obsolete repository's durable fact is only its migration pointer, and
   the successor's own repository is the better source if an actual need for an inline browser emerges. Softening the
   obsolete capture into a reference would preserve no unique reusable knowledge.

The contrary case is real: a concrete workflow that needs a person to watch and seize an agent's browser without
leaving Herdr could justify evaluating Terminal Browser. That should be a fresh decision about the successor, with a
pinned package, telemetry disabled by policy, and proof in both WezTerm-on-chise and the darwin terminal path. This
capture does not supply that need.
