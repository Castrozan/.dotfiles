## What it actually is

A prompt-only skill for asking a coding agent to replace long explanations with the smallest useful visual. It offers
examples for pseudocode, call trees, component trees, shallow file trees, Mermaid sequences, focused diffs, type
signatures, and one-off HTML explainers. It adds no runtime, parser, renderer, or dependency; the model produces the
representation directly in its reply or writes an HTML file and opens it.

The useful principle is narrower than "make everything visual": pick the representation that carries the relationship,
keep only the calls, files, state, and boundaries needed for the current question, and leave a simple linear answer as
prose.

has regression coverage for both selecting a visual and declining decorative structure. The upstream skill would make

Drop, rather than learn: there is no missing practice to schedule. The existing Humanize evaluations exercise the
behavior directly.

Drop, rather than reference: the durable value of the source is its representation-selection rule, and that rule is
already encoded and tested here. Filing another note would preserve an upstream prompt whose actionable content has
already been absorbed, not unblock a future decision.

The HTML path is the strongest reason to disagree with this verdict. If repeated user requests show that Mermaid,
trees, diffs, and wireframes are insufficient, the narrow follow-up would be to add a tested HTML-artifact mode to the
owner that already selects representations. That evidence does not exist in this capture, and adding the whole
`show-me` skill now would be a second policy owner for one speculative branch.

Cost of dropping: no new `/show-me` invocation name and no canned HTML-explainer workflow. Cost avoided: another skill
to expose, evaluate, and keep consistent with Humanize.
