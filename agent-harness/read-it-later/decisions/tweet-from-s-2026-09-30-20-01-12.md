## Why drop

The first plausible use was to turn the listed tools into a producer agent. The source does not justify that decision:
its revenue claim is unverified, its prompt is generic, and its tool list omits the expensive and consequential parts
of the system. Wiring those providers now would prove only that APIs can be called, not that outputs are accurate,
distinct, watchable, rights-safe, affordable, or publishable.

A trial is the strongest way to test that uncertainty, but PR #192 already carries the better trial. It covers this
article's useful production stages while adding explicit budgets, acceptance criteria, private uploads, policy limits,
and factual review. Opening a second trial from a weaker source would split one decision across two pull requests and
risk implementing whichever duplicate happened to be approved first.

This is not a `learn`: hooks, curiosity loops, batching, and click-through-rate testing are advice, not a bounded skill
practice with evidence or feedback that this repository needs to create. It is not a `reference`: the article has no
unique data, artifact, or accountable case study worth preserving after the stronger trial decision record exists.
Calling it a reference would retain an unsupported earnings headline merely to avoid discarding it.

The drop applies only to this capture. It does not reject the automated-video direction and does not answer PR #192;
Lucas can still approve, reject, or revise that independent trial on its own evidence.
