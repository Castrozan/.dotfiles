## The origin as resolved

Read through the twitter skill (`twikit-cli tweet 2104806420524962257`), not a search. Rivon (@Rivonn)
posted it on 2026-09-29 and describes `LTX Video 2.3 Uncensored Turbo v1.4` as a community build that can
make 40-second clips with sound locally. The post itself does not link to the model distribution: its
embedded `https://t.co/T8ddZcThNY` redirects to an older Rivon post about a different Wan 1.3B model.

After reading the origin, the exact model name resolves to the publisher's Hugging Face model card:
https://huggingface.co/ChrisColeTech/LTX-2.3-uncensored-v1.4-FP8. That card says this is a pre-merged,
quantized LTX-2.3 derivative with an adult-content LoRA, a distilled LoRA and LTX's IC-LoRA Detailer. It
documents 4- to 8-step generation, synchronized audio, and a 960-frame / 40-second maximum. The claimed
capability is real; the tweet omits the hardware, software and distribution costs that decide whether it
belongs here.

## What it actually is

A third-party bundle of a 21B-parameter audio-video model for ComfyUI, not a standalone application. The
publisher's recommended component set is a 17.8 GB Q6 transformer, 7.3 GB Gemma text encoder, 2.31 GB
projection model, 1.45 GB video VAE and 365 MB audio VAE: about 29.2 GB of weights before ComfyUI, model
working memory or generated frames. The smallest listed Q4 transformer is still 14.2 GB by itself.

The Hugging Face repository declares its license as unknown, requires the current nightly GGUF loader, and
has no inference-provider deployment. The same publisher released an LTX-2.5 successor by 2026-09-10, so
this captured v2.3 merge is already a superseded point build rather than a durable local capability.

## What it touches here

Nothing to adopt on the machines this repository owns.

`machine-configuration/machines/chise/system/configs/nvidia-policy.md:3` identifies chise's laptop-class
RTX 3050 GPU, while `machine-configuration/machines/chise/system/configs/nvidia.nix:60-62` supplies CUDA
but no local media-generation service. A live read-only check,
`nvidia-smi --query-gpu=name,memory.total,driver_version --format=csv,noheader,nounits`, reports an NVIDIA
GeForce RTX 3050 Laptop GPU with 4096 MiB of VRAM. Even the 14.2 GB Q4 transformer is over three times that
capacity before the required encoder, projection model, VAEs and inference state. CPU offload could turn
the mismatch into waiting rather than a hard load failure, but it would not make this a credible 720p,
40-second local workflow.

A search of `origin/main` finds no ComfyUI, LTX or local image/video-generation module to extend. Adopting
this would therefore add an entire runtime, nightly custom node and roughly 25-29 GB of model artifacts; it
would replace or delete nothing and would not unblock an existing workflow.

## Reasoning

Drop, rather than trial: the decisive constraint is not uncertainty about output quality but a documented
hardware mismatch. A useful trial would need different hardware or a paid remote machine, which no longer
tests the tweet's proposition that this runs locally on the machine configured here.

Drop, rather than reference: this is a fast-moving, already-superseded third-party merge with an unknown
declared license. The durable fact is only that open-weight audio-video generation exists; retaining this
specific v2.3 checkpoint would preserve a stale download recommendation, not reusable knowledge. If local
video generation becomes an actual requirement, it should start from the then-current model and measured
hardware budget rather than from this capture.
