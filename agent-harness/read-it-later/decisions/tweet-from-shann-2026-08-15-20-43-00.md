## What it actually is

This is an elicitation protocol, not a planning tool or an autonomous builder. Its useful mechanism is the decision
frontier: ask only questions whose prerequisites are already settled, then recompute what can be asked after each
answer. That prevents later questions from smuggling in guesses about decisions the user has not made.

The upstream packaging has a current selective-install trap: `grill-me` contains no interview logic and fails when the
separate `grilling` skill is absent, as reported in upstream issues
[#685](https://github.com/mattpocock/skills/issues/685) and
[#866](https://github.com/mattpocock/skills/issues/866). The mechanism itself has no runtime, service, dependency or
persistent state.

## Reasoning

Adopt, because the repo has the downstream execution disciplines but no user-invoked capability for resolving the
decisions that precede them. The capture's marketing example is useful evidence that the protocol is domain-neutral;
the local skill therefore belongs in the shared agent instruction surface rather than in a marketing-specific module.

Copying the upstream files verbatim would import an avoidable alias dependency and formatting that conflicts with the
repo's instruction contract. The native version keeps the distinctive parts that change agent behavior and drops the
presentation template, fixed question counts, emoji and instruction to always dispatch a subagent. Fact-finding stays
mandatory, but the agent can use the cheapest available context or tool instead of creating concurrency for its own
sake.

This is not a trial: the behavior is plain instruction text, reversible in one commit, and covered by the existing
instruction lint and three-harness catalog checks. It is not a reference because it closes a concrete gap in the current
skill set without adding operational burden.

## What it is

`grilling` is a structured interview for a loose plan, decision or idea. It models unresolved choices as a prerequisite
tree, asks the whole currently unblocked frontier in each round, and gives a recommended answer beside every question.
Facts remain the agent's responsibility; decisions remain the user's. The session ends only after the frontier is empty
and the user confirms the shared understanding.

Shann Holmberg's useful extension is to stop talking when an answer depends on something observable. Make the cheapest
draft or probe that can supply evidence, react to it, then return to the decision tree. Pushback matters: accepting every
recommendation produces an agent-owned plan even if the user typed every confirmation.

## What to steal

- Ask only decisions whose prerequisites are settled; recompute the frontier after every reply.
- Put a recommendation beside each question so the trade-off is concrete without transferring ownership to the agent.
- Investigate facts instead of asking the user to retrieve them.
- Use cheap observable evidence when prose would force a guess, then resume the interview.
- Require a final shared-understanding confirmation before acting.
